::::part Арифметика

Пять арифметических операторов: `+`, `-`, `*`, `/` и `%` (остаток от деления).

**Деление целых чисел отбрасывает дробную часть** — округляет к нулю:

```csharp
Console.WriteLine(7 / 2);    // 3
Console.WriteLine(-7 / 2);   // -3, а не -4: к нулю
Console.WriteLine(7 % 2);    // 1
Console.WriteLine(-7 % 2);   // -1: знак остатка — как у делимого
Console.WriteLine(7 / 2.0);  // 3.5: один операнд дробный, деление дробное
```

Если оба числа лежат в переменных `int`, а нужен дробный результат, одно из них явно превращают в `double`: `(double)a / b`. Такая запись называется приведением, о нём — отдельная тема.

**Деление на ноль** зависит от типа. Целое деление на ноль бросает исключение `DivideByZeroException`. Если делитель — константа `0`, компилятор заметит ошибку ещё при сборке. Дробное деление на ноль исключения не бросает, а даёт бесконечность или `NaN`.

**Тип результата** определяется по операндам. Если они разных типов, меньший расширяется до большего:

| Операнды | Результат |
|---|---|
| `int` и `long` | `long` |
| `int` и `double` | `double` |
| `long` и `float` | `float` |
| `byte` и `byte` | **`int`** |
| `short` и `short` | **`int`** |

Последние две строки — частая ловушка. Арифметика в C# определена только для `int`, `uint`, `long`, `ulong` и дробных типов. Меньшие типы — `byte`, `sbyte`, `short`, `ushort`, `char` — перед вычислением расширяются до `int`. Поэтому так не компилируется:

```csharp
byte a = 10;
byte b = 20;
byte sum = a + b;  // ошибка: результат a + b — int
```

::::part Инкремент и составное присваивание

`++` увеличивает переменную на 1, `--` уменьшает. У каждого две формы, и разница видна, когда результат используют в выражении:

```csharp
int x = 5;
int a = x++;  // постфиксная: a = 5 — старое значение, потом x станет 6
int b = ++x;  // префиксная: x станет 7, b = 7 — новое значение
```

Если инкремент стоит отдельной строкой (`x++;`), формы ничем не отличаются.

**Составное присваивание** — сокращённая запись: `x += 5` то же, что `x = x + 5`. Есть `-=`, `*=`, `/=`, `%=` и другие.

У составного присваивания есть важное отличие: оно само приводит результат к типу переменной.

```csharp
byte b = 10;
b = b + 5;  // ошибка: b + 5 — int
b += 5;     // ок: компилятор пишет b = (byte)(b + 5)
```

::::part Переполнение: checked и unchecked

Вы уже знаете, что при переполнении `int` число заворачивается через границу без ошибки. Это поведение по умолчанию, оно называется **unchecked**. Его выбрали ради скорости: проверка каждой операции стоит времени.

Если переполнение должно быть ошибкой, вычисление оборачивают в **`checked`**. Тогда при выходе за границы бросается исключение `OverflowException`:

```csharp
int big = int.MaxValue;

int a = big + 1;           // -2147483648: молча завернулось
int b = checked(big + 1);  // OverflowException
checked
{
    int c = big * 2;       // OverflowException: проверяется весь блок
}
```

Где `checked` встречается на практике: подсчёт денег, размеры буферов, всё, где тихое неверное число опаснее падения. Проверку можно включить для всего проекта настройкой `<CheckForOverflowUnderflow>true</CheckForOverflowUnderflow>` в `.csproj`. Тогда `unchecked(...)` наоборот отключает её в нужном месте.

Ещё два случая, о которых спрашивают:

- **Выражения из констант** проверяются всегда, ещё при компиляции: `int x = int.MaxValue + 1;` не соберётся.
- **`decimal`** никогда не заворачивается: при переполнении он всегда бросает `OverflowException`, даже без `checked`.

```quiz

type: choice
prompt: Что произойдёт при выполнении кода?
code: |
  int max = int.MaxValue;
  int next = checked(max + 1);

  - "Выведет -2147483648"
  - "Выведет 2147483648"
  - "Бросит исключение OverflowException"
  - "Ошибка компиляции"
answer: 2
explain: |
  `checked` включает проверку переполнения: вместо тихого заворачивания бросается `OverflowException`. Ошибки компиляции нет, потому что `max` — переменная, а не константа.
variants:
  - code: |

      int next = max + 1;
      Console.WriteLine(next);
    answer: 0
    explain: |
      Без `checked` переполнение `int` не проверяется: значение заворачивается к `int.MinValue`, то есть -2147483648.
```

::::part Сравнение и логические операторы

Операторы сравнения `==`, `!=`, `<`, `>`, `<=`, `>=` возвращают `bool`. Логические операторы работают с `bool`:

| Оператор | Значение |
|---|---|
| `!a` | не |
| `a && b` | и: `true`, если оба `true` |
| `a \|\| b` | или: `true`, если хотя бы один `true` |
| `a ^ b` | исключающее или: `true`, если ровно один `true` |

**`&&` и `||` вычисляют правую часть, только если она нужна.** Это называется сокращённым вычислением (short-circuit). Если левая часть `&&` — `false`, результат уже `false`, и правая часть не выполняется. Если левая часть `||` — `true`, результат уже `true`.

На этом построена частая проверка: сначала убедиться, что объект есть, потом обратиться к нему.

```csharp
if (name != null && name.Length > 3)  // при name == null вторая часть не выполнится, ошибки не будет
```

У `&` и `|` с `bool` тот же смысл, но они **всегда вычисляют обе части**. Для логики пишут `&&` и `||`, а `&` и `|` нужны для работы с битами, о ней — ниже на уровне Middle.

```quiz
id: short-circuit
type: output
prompt: Что выведет код?
code: |
  int x = 0;
  bool result = false && ++x > 0;
  Console.WriteLine(x);
answer: "0"
explain: |
  Левая часть `&&` — `false`, значит результат уже известен, и правая часть `++x > 0` не выполняется. `x` остаётся 0.
variants:
  - code: |
      int x = 0;
      bool result = false & ++x > 0;
      Console.WriteLine(x);
    answer: "1"
    explain: |
      `&` с `bool` всегда вычисляет обе части, даже если результат известен по левой. `++x` выполняется, и `x` становится 1.
  - code: |
      int x = 0;
      bool result = true || ++x > 0;
      Console.WriteLine(x);
    explain: |
      Левая часть `||` — `true`, результат уже известен, правая часть не выполняется. `x` остаётся 0.
```

::::part Условный оператор и операторы для null

**Условный (тернарный) оператор** `условие ? a : b` возвращает `a`, если условие истинно, и `b` — если нет:

```csharp
int age = 20;
string status = age >= 18 ? "взрослый" : "ребёнок";
```

Обе ветки должны давать совместимые типы. Тернарный оператор удобен для простого выбора значения; если веток больше или в них есть действия, лучше `if`.

Переменная ссылочного типа, например строка, может не указывать ни на какой объект. Тогда в ней лежит **`null`**. Для таких переменных есть три оператора:

```csharp
string? name = null;  // ? после типа: здесь может быть null

string shown = name ?? "гость";  // ?? — левое значение, а если оно null, то правое
name ??= "гость";                // ??= — присвоить, только если сейчас null
int? length = name?.Length;      // ?. — обратиться к члену, только если не null, иначе результат null
```

`?.` возвращает `null`, если объекта нет, поэтому результат `name?.Length` — не `int`, а `int?`, тип, который может хранить `null`. Подробно о `null` и таких типах — в теме про `null`.

```quiz
id: coalesce
type: output
prompt: Что выведет код?
code: |
  string? name = null;
  Console.WriteLine(name ?? "гость");
answer: гость
explain: |
  `??` возвращает левое значение, если оно не `null`, а иначе — правое. `name` равен `null`, поэтому выводится «гость».
variants:
  - code: |
      string? name = "Анна";
      Console.WriteLine(name ?? "гость");
    answer: Анна
    explain: |
      `name` не `null`, поэтому `??` возвращает его, и правая часть даже не вычисляется.
  - code: |
      string? name = null;
      name ??= "Анна";
      name ??= "Борис";
      Console.WriteLine(name);
    answer: Анна
    explain: |
      Первое `??=` присваивает «Анна», потому что `name` был `null`. Второе ничего не делает: `name` уже не `null`.
```

:::level middle

**Побитовые операторы** работают с отдельными битами целых чисел:

| Оператор | Что делает | Пример |
|---|---|---|
| `&` | и для каждого бита | `0b1100 & 0b1010` = `0b1000` |
| `\|` | или | `0b1100 \| 0b1010` = `0b1110` |
| `^` | исключающее или | `0b1100 ^ 0b1010` = `0b0110` |
| `~` | инверсия всех битов | `~0` = `-1` |
| `<<`, `>>` | сдвиг влево и вправо | `1 << 3` = 8, `16 >> 2` = 4 |
| `>>>` | сдвиг вправо без знака (C# 11) | старшие биты заполняются нулями |

Где встречаются: флаги в одном числе (`permissions & Write`), быстрые проверки (`(n & 1) == 0` — число чётное), хеш-функции. Сдвиг влево на k — умножение на 2ᵏ, вправо — деление на 2ᵏ для неотрицательных чисел. Подробнее о флагах — в теме про `enum`.

```quiz
id: bit-shift
type: output

code: |

answer: "16"
explain: |
  Сдвиг влево на 4 бита умножает на 2⁴: `0b1` становится `0b10000`, то есть 16.

  - code: |
      Console.WriteLine(0b1100 & 0b1010);
    answer: "8"
    explain: |
      `&` оставляет единицу только там, где она в обоих числах: `1100 & 1010 = 1000`, это 8.
  - code: |

    explain: |
      `|` ставит единицу, где она хотя бы в одном числе: `1100 | 0011 = 1111`, это 15.
```

::::part Приоритет операторов

Операторы с более высоким приоритетом выполняются раньше: `2 + 3 * 4` — это 14, а не 20. Порядок от высшего к низшему:

| Группа | Операторы |
|---|---|
| первичные | `x.y`, `x?.y`, `f(x)`, `a[i]`, `x++`, `x--` |
| унарные | `+x`, `-x`, `!x`, `~x`, `++x`, `--x`, приведение `(T)x` |
| мультипликативные | `*`, `/`, `%` |
| аддитивные | `+`, `-` |
| сдвиги | `<<`, `>>`, `>>>` |
| сравнение | `<`, `>`, `<=`, `>=`, `is`, `as` |
| равенство | `==`, `!=` |
| логические и побитовые | `&`, затем `^`, затем `\|` |
| условные логические | `&&`, затем `\|\|` |
| null-объединение | `??` |
| условный | `?:` |
| присваивание | `=`, `+=`, `??=` и другие |

Запоминать всю таблицу не нужно. Достаточно помнить, что арифметика выполняется раньше сравнения, сравнение — раньше `&&`, а `&&` — раньше `||`. В остальных случаях ставят скобки: они ничего не стоят и делают код понятнее.

Одна неочевидная пара: `??` ниже арифметики. `count ?? 0 + 1` значит `count ?? (0 + 1)`, а не `(count ?? 0) + 1`.

```quiz
id: precedence
type: output
prompt: Что выведет код?
code: |
  Console.WriteLine(2 + 3 * 4 - 6 / 2);
answer: "11"
explain: |
  Сначала умножение и деление: `3 * 4 = 12`, `6 / 2 = 3`. Потом слева направо: `2 + 12 - 3 = 11`.
variants:
  - code: |
      Console.WriteLine((2 + 3) * 4 % 6);
    answer: "2"
    explain: |
      Скобки первыми: `5`. Затем `*` и `%` слева направо: `5 * 4 = 20`, `20 % 6 = 2`.
  - code: |
      Console.WriteLine(10 - 4 - 3);
    answer: "3"
    explain: |
      Операторы одного приоритета выполняются слева направо: `(10 - 4) - 3 = 3`.
```

::::traps

- **`7 / 2` — это 3.** Деление двух целых отбрасывает дробную часть. Для дробного результата нужен хотя бы один дробный операнд.
- **`byte + byte` — это `int`.** Арифметика для типов меньше `int` не определена, они расширяются.
- **`b += 1` компилируется там, где `b = b + 1` — нет:** составное присваивание само приводит тип.
- **`x++` в выражении даёт старое значение**, `++x` — новое.
- **Переполнение `int` по умолчанию молчит.** Для проверки — `checked` или настройка проекта.
- **`&&` и `||` могут не выполнить правую часть.** Не кладите туда действия, которые должны выполниться всегда.
- **`??` ниже арифметики:** `a ?? 0 + 1` — это `a ?? 1`.

```quiz
prompt: Расскажите о ловушках арифметики в C# и о том, чем `&&` отличается от `&`.
answer: |
  Деление целых отбрасывает дробную часть с округлением к нулю, остаток берёт знак делимого. Целое деление на ноль бросает `DivideByZeroException`, дробное даёт бесконечность или `NaN`.
  Тип результата — больший из типов операндов, но `byte`, `short` и `char` всегда расширяются до `int`, поэтому `byte + byte` — `int`. Составное присваивание (`+=`) само приводит результат к типу переменной.
  Переполнение по умолчанию не проверяется (unchecked): число заворачивается. `checked` превращает его в `OverflowException`; константы проверяются при компиляции, `decimal` проверяется всегда.
  `x++` возвращает старое значение, `++x` — новое.
  `&&` и `||` вычисляют правую часть, только если она нужна, а `&` и `|` — всегда. Для логики используют `&&` и `||`, для битов — `&` и `|`.
```
