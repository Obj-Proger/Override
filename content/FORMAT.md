# Формат содержимого

Каждая подтема — один Markdown-файл с YAML-метаданными. Сборщик проверяет файл и превращает его в HTML и данные для вопросов. Ошибка в формате останавливает сборку.

## Расположение

```
content/<язык>/<стек>/<технология>/<тема>/<подтема>.md
content/ru/dotnet/csharp/type-system/boxing.md
```

Каждая папка — раздел, её название и место задаёт `_section.yml`. Без него сборка падает:

```yaml
title: Система типов
order: 1
```

Имена папок и файлов становятся адресом страницы (`/dotnet/csharp/type-system/boxing`), поэтому пишутся строчными латинскими словами через дефис. Темы раздела идут по `order`, затем — темы вложенных разделов.

## Метаданные

```yaml
---
id: csharp.types.boxing        # уникален на весь сайт, не меняется после публикации
title: Boxing и unboxing
level: junior                  # junior | middle | senior: для какого уровня тема; темы выше уровня читателя помечаются
tracks: [backend, fullstack]   # backend | frontend | fullstack
minutes: 20                    # оценка времени, вес темы в прогрессе
order: 3
requires: [csharp.types.value-reference, csharp.oop.interfaces]  # темы, которые нужно знать до этой
quickCheck: [boxing-copy, boxing-where, unboxing-runtime]       # «Я это знаю»: 3–4 вопроса
---
```

В `quickCheck` 3–4 вопроса уровня самой темы, которые проверяются автоматически и за секунды: `choice`, `multi`, `input`, `output`, `fill`, `find-bug`, `parsons`.

## Предварительные знания

Вопросы и задания проверяют только то, что объяснено в самой теме или в темах из `requires`. Если для объяснения нужно понятие из более поздней темы, его называют одной фразой («такая ошибка называется `InvalidCastException`»), но не спрашивают о нём.

Сборщик проверяет, что темы из `requires` стоят в программе раньше — так цикл невозможен. Тема из `requires`, которая ещё не написана, даёт предупреждение, а не ошибку: содержимое пишется постепенно.

## Код

Код в статье — обычный блок Markdown с языком: ` ```csharp ` или ` ```sql `. Сборщик раскрашивает его заранее, в цветах Visual Studio: C# — через Roslyn, поэтому класс, структура, метод и локальная переменная различаются цветом. Сниппет на C# разбирается как файл с top-level statements и стандартными `using` (`System`, `System.Linq`, `System.Collections.Generic`, `System.Threading.Tasks` и другие), их не нужно писать. Блоки на других языках показываются без подсветки.

## Рисунки

Рисунок — SVG-файл рядом со статьёй:

```markdown
![Описание для экранного диктора](boxing-memory.svg "Подпись под рисунком")
```

Сборщик встраивает SVG прямо в страницу, поэтому цвета рисунка следуют теме сайта. В SVG цвета задаются только через переменные с запасным значением для светлой темы: `fill: var(--fig-panel, #F3F2F7)`. Доступные переменные: `--fig-panel`, `--fig-cell`, `--fig-line`, `--fig-text`, `--fig-muted`, `--fig-accent`, `--fig-accent-soft`, `--fig-ok`, `--fig-ok-soft`, `--fig-err`, `--fig-err-soft`. Обязательны `<title>` и `<desc>` с описанием рисунка словами.

Классы и `id` действуют только внутри рисунка: сборщик добавляет к ним имя файла, поэтому `.big` в двух рисунках на одной странице не конфликтуют. У корневого `<svg>` не должно быть `class` и `id`, а в `<style>` — только простые правила, без `@media` и других `@`-правил.

Рисунок нужен везде, где речь о памяти, порядке выполнения, потоках данных или устройстве структуры: это объясняется картинкой быстрее, чем текстом.

## Структура урока

Урок делится на шаги. Каждый шаг — контейнер из четырёх двоеточий `::::`. Шаги идут в верхнем баре в порядке файла.

| Контейнер | Назначение | Обязателен |
|---|---|---|
| `::::warmup` | вопрос до объяснения («что выведет») | нет |
| `::::part Название` | порция объяснения на 3–5 минут, заканчивается 1–2 вопросами | да, хотя бы одна |
| `::::example Название` | разобранный пример | нет |
| `::::practice` | задания по нарастающей | нет |
| `::::traps` | ловушки | нет |
| `::::summary` | итог: ровно один вопрос `recall` | да |

В `::::summary` поле `answer` вопроса `recall` и есть «Кратко»: оно скрыто, пока пользователь не попробует ответить.

## Блоки уровня

Материал глубже основного уровня темы. Блок уровня — контейнер из трёх двоеточий `:::`, он вкладывается в шаг:

```markdown
:::level middle
Текст, код и вопросы, видимые с уровня Middle.
:::
```

Ниже выбранного уровня блок заменяется строкой «Есть материал уровня …» с кнопкой «Показать».

## Вопросы

Вопрос — блок кода с языком `quiz`, внутри YAML. Общие поля:

```yaml
id: boxing-copy          # уникален внутри темы
type: output             # см. таблицу
level: junior            # необязательно, по умолчанию уровень темы
prompt: Что выведет код?
code: |                  # необязательно: код к вопросу, для output, fill и find-bug обязателен
  ...
explain: |               # разбор, показывается после ответа
  ...
```

| type | Что делает пользователь | Специальные поля |
|---|---|---|
| `choice` | выбирает один вариант | `options`, `answer` (индекс с 0) |
| `multi` | выбирает несколько | `options`, `answer` (список индексов) |
| `input` | вводит значение | `answer` (строка или список допустимых), `caseSensitive` |
| `output` | вводит вывод программы | `code`, `answer` |
| `recall` | вспоминает ответ, сам оценивает | `answer` (эталон) |
| `fill` | заполняет пропуск `___` в коде | `code`, `answer` |
| `find-bug` | выбирает строку с ошибкой | `code`, `answer` (номер строки с 1) |
| `parsons` | собирает код из строк | `lines` (в правильном порядке), `distractors` |
| `code` | пишет код, тесты проверяют | `lang`, `starter`, `tests`, `solution` |
| `sql` | пишет запрос | `setup`, `solution`, `ordered` |

Сравнение для `input`, `output`, `fill`: пробелы по краям и переводы строк в конце не важны. Регистр важен, только если `caseSensitive: true`.

### Задания с кодом

`code`: пользовательский код компилируется вместе с `tests`. Тесты — последовательность операторов C#, которые выполняются по порядку внутри сгенерированного метода; доступны `Assert.Equal`, `Assert.True`, `Assert.Throws<T>`. Пользователю показывается первая проваленная проверка. `solution` — эталон, показывается после решения или по кнопке «Сдаться». Сборщик прогоняет `tests` на `solution`: эталон, который не проходит свои тесты, останавливает сборку.

`sql`: `setup` создаёт таблицы и данные в PGlite, `solution` — эталонный запрос. Результаты сравниваются как множества строк, при `ordered: true` — с учётом порядка.
